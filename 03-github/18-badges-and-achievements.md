# GitHub Badges and Achievements

**Difficulty:** 🟢 Beginner | **Time:** 25 minutes

GitHub achievements are badges that appear on your profile when you do specific things - merge pull requests, star repositories, answer community questions and more. They are completely free to earn, visible to anyone who visits your profile and a subtle but real signal of how actively you participate in the GitHub ecosystem. This file covers every current achievement, every tier threshold and exactly how to earn the three fastest badges available to a brand new account.

## Where Achievements Appear

Achievements appear on your GitHub profile page at `github.com/YOUR_USERNAME`, in the panel on the left side of the page beneath your bio and stats. Each achievement shows as a small circular badge with an icon. Hover over any badge to see its name and a short description.

Clicking on an achievement opens a detail panel showing:

- The badge name and description
- How you earned it
- Your current tier (if the badge has tiers)
- What is required for the next tier

Achievements are visible to everyone who visits your profile unless you hide them.

---

## Showing and Hiding Achievements

You can hide all your achievements from your public profile if you prefer a cleaner look or simply do not want them displayed.

**To hide achievements:**

1. Click your profile photo in the top-right corner of any GitHub page
2. Click **Settings**
3. In the left sidebar, click **Profile**
4. Scroll down to the **Achievements** section
5. Untick **Show achievements on my profile**
6. Click **Save**

This hides all achievements at once. There is no option to hide individual achievements while keeping others visible.

**To show achievements again:**

Follow the same steps and re-tick the box.

> [!NOTE]
> Hiding achievements does not delete them. They are still being tracked in the background and will reappear if you choose to show them again.

## Every Achievement - Full List

GitHub currently has nine achievements. Seven can be actively earned by anyone today. Two (Arctic Code Vault Contributor and Mars 2020 Helicopter Contributor) are permanently retired and no longer earnable.

---

### Pull Shark

**What it is:** Earned by having pull requests merged into the default branch of any repository.

**Tier thresholds:**

| Tier               | PRs Merged |
| ------------------ | ---------- |
| Default (no medal) | 2          |
| Bronze 🥉          | 16         |
| Silver 🥈          | 128        |
| Gold 🥇            | 1024       |

**Notes:**

- The PR must be merged, not just opened or closed without merging
- You can merge PRs into your own repositories to count towards this badge
- PRs merged into private repositories do count
- Each unique merged PR counts once regardless of how many commits it contains

---

### YOLO

**What it is:** Earned by merging a pull request without any code review - no one approves, requests changes or submits a review before the merge.

**Tiers:** None. This is a one-tier badge.

**Notes:**

- You can merge a PR in your own repository with no reviewers added and no review submitted
- The repository does not need branch protection rules - just open a PR and merge it immediately
- Works in both public and private repositories
- Widely considered the easiest badge to earn after Quickdraw

---

### Quickdraw

**What it is:** Earned by closing an issue or pull request within 5 minutes of it being opened.

**Tiers:** None. This is a one-tier badge.

**Notes:**

- You can open and immediately close your own issue or PR in any repository you have access to, including your own
- The 5-minute window is strict - the close action must happen within 5 minutes of the open timestamp
- Closing an issue as "not planned" counts
- Closing a PR without merging it counts

---

### Pair Extraordinaire

**What it is:** Earned by co-authoring commits that get merged into a pull request.

**Tier thresholds:**

| Tier               | Co-authored PRs Merged |
| ------------------ | ---------------------- |
| Default (no medal) | 1                      |
| Bronze 🥉          | 10                     |
| Silver 🥈          | 24                     |
| Gold 🥇            | 48                     |

**Notes:**

- A co-authored commit uses the `Co-authored-by:` trailer in the commit message:

  ```
  Co-authored-by: Name <email@example.com>
  ```

- Both the author and the co-author receive credit towards this achievement
- The co-authored commit must be part of a merged PR, not just pushed to a branch
- This is the achievement most often earned by collaborating on a shared repository

---

### Starstruck

**What it is:** Earned when other users star a repository that you own or have created.

**Tier thresholds:**

| Tier               | Stars on a Single Repository |
| ------------------ | ---------------------------- |
| Default (no medal) | 16                           |
| Bronze 🥉          | 128                          |
| Silver 🥈          | 512                          |
| Gold 🥇            | 4096                         |

**Notes:**

- Stars must be on a **single repository** - they do not aggregate across all your repositories
- Stars on forked repositories do not count
- The repository must be public
- You cannot star your own repository to earn this badge

---

### Galaxy Brain

**What it is:** Earned when your answer to a GitHub Discussion is marked as the accepted answer.

**Tier thresholds:**

| Tier               | Accepted Answers |
| ------------------ | ---------------- |
| Default (no medal) | 1                |
| Bronze 🥉          | 8                |
| Silver 🥈          | 16               |
| Gold 🥇            | 32               |

**Notes:**

- The discussion must be in a repository that has the Discussions feature enabled
- Only the repository owner or a maintainer with the correct permissions can mark an answer as accepted
- You cannot mark your own answer as accepted in the same discussion where you posted the question
- The category must be a Q&A-type discussion, not Announcements, General or Polls

---

### Public Sponsor

**What it is:** Earned by sponsoring a developer or organisation through GitHub Sponsors.

**Tiers:** None. This is a one-tier badge.

**Notes:**

- The sponsorship must be a paid sponsorship - there is no free tier that qualifies
- The sponsorship must be made publicly (not privately)
- You earn this badge immediately once your first public sponsorship is active
- GitHub Sponsors is available in most countries; availability of the payment option depends on your region

---

### Arctic Code Vault Contributor

**What it is:** Awarded to developers whose code was included in the GitHub Arctic Code Vault snapshot taken on 02 February 2020. GitHub archived a snapshot of all active public repositories to the Arctic World Archive in Svalbard, Norway.

**Status:** Permanently retired. You cannot earn this badge today.

**Who has it:** Anyone who had code committed to a public repository before the snapshot date.

---

### Mars 2020 Helicopter Contributor

**What it is:** Awarded to developers who contributed code that was used in the Mars 2020 Helicopter mission (the Ingenuity helicopter). GitHub identified open source projects that NASA's Jet Propulsion Laboratory used in the mission and awarded the badge to contributors of those projects.

**Status:** Permanently retired. You cannot earn this badge today.

**Who has it:** Contributors to specific open source libraries identified by NASA/JPL as used in the Ingenuity mission.

## Highlight Badges - Special Status Badges

Highlight badges are different from achievements. They appear in the same area of your profile but represent official GitHub program memberships or certifications rather than activity milestones. They cannot be earned through regular activity - they require applying for and being accepted into a specific program.

**GitHub Pro:**

Shown automatically on your profile when you are a GitHub Pro subscriber. Pro is included in GitHub Student Developer Pack at no cost for verified students.

**Developer Program Member:**

Shown when you register as a GitHub Developer Program member. This is free and available to anyone building on the GitHub API or GitHub Apps. Register at `github.com/developers`.

**GitHub Campus Expert:**

Shown when you are an accepted GitHub Campus Expert. This is a competitive program for student leaders who run technical communities at their university. Application is open once or twice per year. Details at `education.github.com/experts`.

**GitHub Security Bug Bounty Hunter:**

Shown when you have reported a valid security vulnerability to GitHub through their bug bounty programme (via HackerOne).

**GitHub Star:**

A rare badge awarded to exceptional community members who educate, inspire and help grow the GitHub community. Nominated and selected by GitHub staff. Details at `stars.github.com`.

> [!NOTE]
> Highlight badge visibility is controlled by the same setting as achievements. Hiding achievements also hides highlight badges.

## Three Quick Badges for a Brand New Account

These three badges can be earned within minutes of creating a GitHub account. You need no followers, no existing repositories with stars and no collaborators. All three work on a fresh account.

---

### Badge 1 - Quickdraw

**What it earns:** The Quickdraw badge.

**What you need:** A repository, an issue or PR and the ability to close it within 5 minutes of opening.

**Step-by-step:**

**Step 1.** Sign in to GitHub at `github.com`.

**Step 2.** Create a new repository:

- Click the **+** icon in the top-right corner
- Click **New repository**
- Name it anything - for example `quickdraw-test`
- Set it to **Public** or **Private** (either works)
- Tick **Add a README file** so the repository is initialised
- Click **Create repository**

**Step 3.** Open an issue:

- In your new repository, click the **Issues** tab
- Click **New issue**
- Give it any title - for example `Test issue`
- Click **Submit new issue**

**Step 4.** Close the issue immediately:

- You are now viewing the open issue
- Scroll down to the comment box
- Click **Close issue** (the button at the bottom right of the comment area or use the dropdown to select **Close as not planned**)

That is it. As long as you closed it within 5 minutes of opening it - which you will have done since you opened and closed it back-to-back - the Quickdraw badge is awarded. It may take a few minutes to appear on your profile.

> [!TIP]
> If you want to be extra certain, check the issue's timestamp after opening it before you close it. The creation time and close time are both recorded. As long as the gap is under 5 minutes, it counts.

---

### Badge 2 - YOLO

**What it earns:** The YOLO badge.

**What you need:** A repository with at least one commit on a non-default branch and the ability to open and merge a PR with no review.

**Step-by-step:**

Continue in the same `quickdraw-test` repository from Badge 1 or use any repository you own.

**Step 1.** Create a new branch on GitHub:

- In your repository, click the branch dropdown (it says `main` by default, in the top-left of the file list)
- Type a new branch name in the box - for example `yolo-branch`
- Click **Create branch: yolo-branch from 'main'**

**Step 2.** Make a small change on the new branch:

- You are now on `yolo-branch`
- Click on `README.md` in the file list
- Click the pencil (edit) icon
- Add one line of text anywhere in the file - for example `<!-- yolo edit -->`
- Scroll down to the **Commit changes** section
- Make sure **Commit directly to the `yolo-branch` branch** is selected
- Click **Commit changes**

**Step 3.** Open a pull request:

- GitHub will show a yellow banner saying your branch has recent pushes with a **Compare and pull request** button - click it
- Or go to the **Pull requests** tab and click **New pull request**, then set base to `main` and compare to `yolo-branch`
- Give the PR any title
- **Do not add any reviewers** - leave the Reviewers panel completely empty
- Click **Create pull request**

**Step 4.** Merge immediately without review:

- You are now viewing the open PR
- Scroll down to the merge section
- Click **Merge pull request**
- Click **Confirm merge**

No one reviewed it. No approval was given. GitHub awards the YOLO badge. It may take a few minutes to appear on your profile.

> [!NOTE]
> If your repository has branch protection rules that require approvals before merging, YOLO cannot be earned this way because GitHub will block the merge. On a freshly created repository there are no branch protection rules by default, so you are fine.

---

### Badge 3 - Pull Shark (Default Tier)

**What it earns:** The Pull Shark badge (default tier, no medal colour) for having 2 pull requests merged.

**What you need:** 2 merged pull requests. The YOLO badge step above already counts as 1.

**Step-by-step:**

You already merged one PR for the YOLO badge. You need one more merged PR.

**Step 1.** Create another branch:

- In your repository, click the branch dropdown showing `main`
- Type `pull-shark-branch` and click **Create branch: pull-shark-branch from 'main'**

**Step 2.** Make a change on the new branch:

- Click `README.md`
- Click the pencil icon
- Add another line - for example `<!-- pull shark edit -->`
- In the Commit changes section, confirm **Commit directly to the `pull-shark-branch` branch** is selected
- Click **Commit changes**

**Step 3.** Open a pull request:

- Click the **Compare and pull request** banner or go to the **Pull requests** tab
- Title it anything
- Click **Create pull request**

**Step 4.** Merge it:

- Click **Merge pull request**
- Click **Confirm merge**

That is your second merged PR. The Pull Shark badge (default tier) will appear on your profile shortly.

> [!TIP]
> You have now earned three badges in one session using a single repository. Check your profile at `github.com/YOUR_USERNAME` - give it a couple of minutes and refresh. The badges appear in the achievements panel on the left side of your profile.

## Achievement Tiers Explained

Four achievements have multiple tiers: Pull Shark, Pair Extraordinaire, Starstruck and Galaxy Brain.

Tiers work as follows:

- When you first meet the minimum threshold for an achievement, the **default tier** badge appears with no medal indicator
- When you reach the next threshold, the badge upgrades automatically to **Bronze 🥉**
- Further activity upgrades it to **Silver 🥈** then **Gold 🥇**
- There is no action required on your part to upgrade - GitHub updates the badge automatically

The tier displayed on your profile always shows your current highest tier. You do not collect multiple copies of the same badge at different tiers.

**Full tier table:**

| Achievement         | Default                 | Bronze 🥉 | Silver 🥈 | Gold 🥇 |
| ------------------- | ----------------------- | --------- | --------- | ------- |
| Pull Shark          | 2 PRs merged            | 16        | 128       | 1024    |
| Pair Extraordinaire | 1 co-authored PR merged | 10        | 24        | 48      |
| Starstruck          | 16 stars on one repo    | 128       | 512       | 4096    |
| Galaxy Brain        | 1 accepted answer       | 8         | 16        | 32      |
| YOLO                | 1 (no tiers)            | -         | -         | -       |
| Quickdraw           | 1 (no tiers)            | -         | -         | -       |
| Public Sponsor      | 1 (no tiers)            | -         | -         | -       |

## Tips for Earning Achievements

**Pull Shark:** Contribute to open source. Every merged PR to any public repository counts. Fix typos in documentation, add missing examples, improve error messages - these are all valid contributions. Check `github.com/explore` and `goodfirstissue.dev` for repositories welcoming first contributions.

**Pair Extraordinaire:** When collaborating on a project with others, use `Co-authored-by:` trailers in commit messages. If you use VS Code, install the GitLens extension which can add co-authors from a GUI. If you are working on a shared repository with a classmate or colleague, add the trailer to every collaborative commit.

**Starstruck:** Build something genuinely useful and share it. Post it to relevant communities - Reddit (`r/programming`, `r/webdev`, `r/learnprogramming`), Hacker News Show HN, Product Hunt or Discord servers in your technology area. 16 stars is achievable for a useful tool, template or resource.

**Galaxy Brain:** Answer technical questions in repositories where Discussions are enabled. Check `github.com/orgs/microsoft/discussions`, popular open source project discussions or any community you participate in. Quality answers to specific technical problems are most likely to be accepted.

**Public Sponsor:** If you use an open source library or tool regularly and it matters to your work or study, consider sponsoring its maintainer. Even $1/month earns the badge and supports someone doing real work.

> [!IMPORTANT]
> Do not use automated scripts, bots or fake accounts to artificially inflate achievement counts. GitHub's terms of service prohibit this and it risks account suspension. All the achievements above can be earned legitimately through normal use.

## Try It Yourself

Work through the three quick badges above in order. By the end of this exercise you will have:

- Created a repository
- Opened and closed an issue (Quickdraw)
- Created a branch, made a change, opened a PR and merged it without review (YOLO)
- Done the above a second time for a total of two merged PRs (Pull Shark default tier)
- Earned three GitHub badges

**After earning the badges:**

1. Go to `github.com/YOUR_USERNAME`
2. Find the achievements panel on the left side of your profile (below your bio)
3. Hover over each badge to see its name
4. Click any badge to see the full detail panel

**Optional: check your achievement visibility setting:**

1. Go to **Settings → Profile**
2. Scroll to the **Achievements** section
3. Confirm achievements are set to visible

## Common Mistakes

**Waiting too long to close the issue or PR for Quickdraw.** The 5-minute window is strict. Open the issue, then immediately close it. Do not go make a cup of tea first.

**Adding a reviewer before merging for YOLO.** If you add a reviewer and they submit any review - even a comment that is not an approval - YOLO may not be awarded. Leave the Reviewers panel completely empty and merge immediately.

**Merging the PR into a non-default branch for Pull Shark.** The merged PR must target the default branch of the repository (usually `main` or `master`). PRs merged into other branches do not count.

**Expecting badges to appear instantly.** GitHub can take anywhere from a few minutes to a few hours to award achievements after the qualifying action. Refresh your profile, do not panic if it does not appear immediately.

**Starring your own repository.** You cannot star your own repositories. Stars for Starstruck must come from other GitHub accounts.

**Thinking private repositories do not count.** Pull Shark and Pair Extraordinaire count activity in private repositories as well as public ones. Starstruck and Galaxy Brain require public repositories.

**Opening PRs against someone else's fork expecting them to count.** PRs must be merged. If you open a PR and the maintainer closes it without merging, it does not count towards Pull Shark.

**Confusing achievements with Shields.io badges.** GitHub achievements are the official badges in your profile panel. Shields.io badges are custom image badges you add to READMEs yourself (covered in `17-profile-and-readme.md`). They are completely separate things.

## Summary

- GitHub achievements appear on your profile in the left panel and are visible to everyone by default
- You can show or hide all achievements via **Settings → Profile → Achievements**
- There are currently **7 earnable achievements** and 2 permanently retired ones (Arctic Code Vault, Mars 2020)
- Four achievements have tiers: **Pull Shark**, **Pair Extraordinaire**, **Starstruck** and **Galaxy Brain**
- The three fastest badges for a new account are **Quickdraw** (close an issue or PR within 5 minutes of opening), **YOLO** (merge a PR with no review) and **Pull Shark** default tier (2 PRs merged)
- All three can be earned in under 15 minutes using a single repository
- **Highlight badges** (Pro, Campus Expert, GitHub Star etc.) are program memberships, not activity milestones - they require separate applications
- Never use bots or fake accounts to farm achievements - it violates GitHub's terms of service
